# 简历模块登记与新增流程

## 目录职责

- `moduleRegistry.ts`：模块标识、名称、图标、添加权限、常用顺序与预览适配方式的统一登记，不导入表单组件、Store 或预览实现。
- `formConfig.ts`：字段定义与表单绑定；`allConfig`（全部模块表单配置）通过 `ResumeModuleKey`（已登记模块标识）约束，登记和表单必须一一对应。
- `defaultConfig.ts`：简历和编辑器默认值；模块名称列表与自定义图标从统一登记派生，不另写名单。
- `resumeOptions.ts`：字段枚举选项。
- 批注属于模块或条目的编辑信息，不登记为投递正文表单字段；字段类型和读写规则统一维护在 `domain/resume/comments.ts`（批注领域入口），使用方经简历 Store 访问，不在各模块表单中重复声明。

## 登记字段

| 字段 | 中文含义与约定 |
| --- | --- |
| `key` | 稳定模块标识，关联表单、业务数据与同名模块帮助文案，不使用用户修改后的标题作为标识 |
| `name` | 编辑器默认名称，沿用编辑器现有翻译机制 |
| `icon` | 导航和帮助入口共用的图标 |
| `preview` | 预览适配方式，由预览层映射到节点转换实现，不在登记中编写分页逻辑 |
| `addable` | 是否允许通过预设入口添加，省略时允许；固定模块和自定义入口不重复展示 |
| `basicOrder` | 常用模块和一键添加的顺序，省略时归入其他模块 |

全部登记模块自动生成学习中心写作参考入口，正文复用 `moduleHelp_<模块标识>_*`（模块帮助文案）。自定义模块只登记模板，实际实例继续使用动态标识与现有兜底适配器。

## 新增普通模块

1. 在 `moduleRegistry.ts` 登记模块。按内容选择已有预览适配方式，并决定是否允许添加、是否属于常用模块。
2. 在 `formConfig.ts` 定义对象或列表表单，并加入 `allConfig`（全部模块表单配置）。字段类型、默认值、枚举、必填、可添加与拖拽能力以此为源头，不另写一份 AI 字段清单。
3. 确认预览内容接入。经历类和通用富文本可复用现有组件；列表、媒体、学术成果等使用按模块标识选择的内容组件，需要在 `views/resume/theme/components/nodeContent/contents/` 提供对应实现。只有现有适配方式无法表达内容时，才在预览层新增适配方式并登记。
4. 补齐编辑器中英文名称、预览支持语言的标题、模块帮助和 `views/resume/template/data/resumes/recommended/allFields.ts`（全字段范本）的非空示例。学习中心入口自动生成，帮助正文仍需编写。
5. 若有独立展示设置，同步 `domain/resume/theme/` 下的配置类型、默认值、主题合并和设置入口；尺寸变化应进入现有测量监听或节点签名。
6. 按下方清单核对完整链路，不能仅以添加面板出现模块作为接入完成。

## 自动链路与特殊接入

- 表单配置生成公共字段契约，供 AI 读取、写入校验、文档导入与常规 Markdown 导出使用；特殊值和多形态模块仍需确认对应处理逻辑。
- 字段拖拽沿用配置压缩与恢复机制；预览需要读取可排序字段时，应将顺序纳入节点载荷。
- 模块登记选择预览适配器，节点继续使用统一测量与分页，打印、图片和 PDF 等沿用现有预览链路。
- 迁移已有字段的模块，须明确添加与删除动作、公共字段归属、跨模块业务读取；这些逻辑由对应业务维护，不由登记表自动推断。
- 媒体、隐私字段与 AI 优化资格等特殊语义，按实际影响接入对应公共规则，不为普通模块预建迁移框架。
- 求职意向的字段归属在 `packages/resume-core/jobIntent.ts`（公共归属与读取规则），实际迁移动作在 `../hooks/useJobIntent.ts`（编辑器迁入迁出）。

## 完成清单

- 添加入口、常用分组、导航名称及图标正确；列表模块能新增记录。
- 填写、清空、字段和记录排序、隐藏后，编辑与预览一致；刷新后数据与顺序保留。
- 模块帮助和学习中心有对应文案，全字段范本包含有效内容。
- 完整备份导入导出、文档导入和 Markdown 导出能保留应有内容；投递导出遵守隐藏状态。
- 预览、打印、图片和 PDF 使用相同内容与顺序，展示设置变化能重新测量。
- AI 字段契约、读取和写入校验识别新模块；有字段归属迁移时覆盖仅选择个人信息等局部范围。
- 删除后状态正确；有字段迁移时，额外核对已有值、清空值、字段展示状态和迁回位置。

此清单用于明确交付范围，不代表自动执行验证；是否运行构建、测试或页面核对，遵守根目录 `AGENTS.md` 的执行边界。
