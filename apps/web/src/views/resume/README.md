# 简历模块维护指南

本目录维护简历页面、编辑器和用户操作指引。开发约束以项目根目录 `AGENTS.md` 为准。

## 文档维护

- README 只保留目录职责、当前约定、同步要求和必要操作说明；行为变化时直接更新对应段落。
- 不追加“本轮迭代记录”、逐次样式微调、已完成修复、临时排查过程或历次测试结果。
- 修改历史通过 Git 查看；本次验证范围与限制写在提交说明或回复中，不作为长期规则累积。
- 详细约定写在负责该功能的目录，其他位置引用它，不重复维护多份。

## 目录职责

- 简历首页独立使用 `main/homeNavigation.vue` 顶部栏并保持全宽，不复用工作区侧栏；顶部栏只保留品牌、功能按钮与右侧「开始使用」入口，栏目导航统一由工作区侧栏承担。其他非编辑器页面在桌面与侧栏并排展示，侧栏宽度由内容撑开，公共布局按 flex 分配空间、不写死侧栏宽度与内容偏移；功能按钮集中在侧栏底部；窄屏通过左侧抽屉访问同一组导航与底部功能。公共布局负责导航占位，各页面保留自身内容间距。
- 工作区入口页标题统一使用 `text-lg font-semibold text-sf-text`，不额外展示栏目小字；说明文字统一使用 `mt-[6px] text-xs leading-6 text-sf-text-2`。
- 桌面侧栏与移动抽屉共用同一导航分组，按「简历制作」「AI 助手」「设置与记录」「求职工具」「更多」排列；简历制作依次展示简历模板、我的简历，AI 助手包含生成、优化、岗位适配、面试；设置与记录依次展示 AI 使用情况、AI 设置、通用设置，求职工具分类包含求职统计、求职指南、求职工具，「歇会儿」归入最后的更多分类。

## 学习中心同步要求

**简历编辑器的功能新增、删除、改名或操作变化，必须在同一修改中核对并同步学习中心。**

| 位置 | 维护内容 |
| --- | --- |
| `editor/components/header/learningCenter/data.ts` | 分类、文章与模块写作参考的映射 |
| `editor/components/header/learningCenter/learningCenterModal.vue` | 搜索、目录与教程展示 |
| `apps/web/src/locales/lang/zh/resume-editor.json`、`en/resume-editor.json` | `learningCenter*`（操作教程）和 `moduleHelp_*`（模块帮助）文案 |
| `editor/panel/form/components/collapse/helpCenter.vue` | 模块标题旁的帮助弹窗，与学习中心共用模块帮助文案 |

- 教程以功能使用为主：写清从哪里打开、点击什么、操作后得到什么；每步只说明一个动作，使用界面上的真实名称。
- 摘要只说明用途；提示只保留会影响操作的必要限制，避免重复步骤、泛泛建议和实现细节。
- 操作入口、参数、默认行为、可用条件、导入导出格式或 AI 范围变化时，同步对应步骤和提示；删除功能时移除失效教程。
- 中英文同步更新；新增文章时补齐标题、摘要、步骤与必要提示，并登记分类。
- 模块写作属于补充参考，复用 `moduleHelp_*`（模块帮助文案），不在学习中心另写一套。
- 不在教程中描述占位入口或尚未实现的行为；产品教程与开发文档都以当前实现为准。

## 字段与范本

- 模块元信息统一在 `apps/web/src/stores/modules/resume/config/moduleRegistry.ts` 登记，添加分组、预览适配与帮助目录从同一登记派生；表单仍在 `formConfig.ts` 定义，并以已登记模块标识约束完整性。新增流程、自动链路与完成清单见 [模块登记说明](../../stores/modules/resume/config/README.md)。

- 求职意向字段支持拖拽排序，顺序保存在 `config.modules`（模块配置列表）中对应模块的 `fields`（字段顺序列表），沿用现有配置压缩与恢复逻辑；预览、测量和导出读取同一顺序。

- 可选的 `jobIntent`（求职意向模块）集中维护岗位、状态、到岗时间、期望城市和薪资；添加时迁入个人信息中的已有内容与字段展示设置，删除时仅把最新非空内容追加回个人信息末尾，清空项不恢复旧值，也不恢复副标题置顶。参加工作时间留在个人信息，隐藏模块不迁移。模块存在时个人信息不提供这五项的编辑或添加入口，业务岗位读取统一使用公共层的 `getResumeJobField`。`ui.jobIntent.infoMode`（求职意向标签模式）由模块标题旁的设置独立控制，支持文字、图标和仅内容，默认显示文字标签，沿用简历 UI 的默认值展开与覆盖项保存机制。

业务字段以 `apps/web/src/stores/modules/resume/config/formConfig.ts` 为准；Web 侧生成字段契约后注册到 `packages/resume-core/schema/resumeSchemaRegistry.ts`，供两个智能体共用。范本不能反过来定义字段。

| 字段变化 | 必须同步 |
| --- | --- |
| 新增 | 表单与字段契约、受影响链路，以及 `template/data/resumes/recommended/allFields.ts` 的非空示例 |
| 重命名或移除 | 所有受影响范本、读取与写入路径、`resumeTemplateContent_<fileName>_*`（范本正文文案） |
| 类型、枚举、格式、可添加状态或模块形态变化 | 字段校验、完成度、AI 读取与写入、快捷处理、导入及受影响范本 |

- `allFields.ts`（全字段范本）必须覆盖全部模块与已声明业务字段，字段取值应有效且非空。
- `template/data/list.ts` 的 `fileName`（范本文件名）必须对应真实文件；中英文范本正文与主题名称文案须齐全。
- 模块形态由表单配置声明，完成度、AI 当前形态读取和写入校验使用同一结构，不另写静态字段表或模块特例。
- 面向用户的字段和模块变化，还须按上节同步学习中心与模块帮助。

## AI 维护边界

### 唯一规则与职责

- 模型配置集中在“小舟AI”页，编辑器右侧“AI 设置”复用 `editor/toolbar/modules/ai/content.vue`。顶部角色设置带展示简历助手小舟、简历解析、面试官小羊三个角色绑定，宽屏三列排列，窄屏纵向排列，小羊独立选择面试模型，不继承或回退到小舟；下方统一为服务商配置界面，不再切换模型库与添加页。服务商通过下划线导航切换；连接配置集中在浅底区域，密钥与接口入口按容器宽度并排或纵向展示，下方使用连续模型清单。API 密钥和有效接口地址随输入自动保存；已添加模型使用连续列表展示，可检测连接、查看绑定角色和删除，点击“添加模型”通过弹窗填写模型与别名，沿用已保存的服务商凭据并检测后添加。密钥独立持久化到 `providerCredentials`（服务商凭据表），兼容旧模型中已有的密钥；密钥与有效接口地址随输入自动保存，清空密钥后不能添加模型，无需手动确认。切换服务商保留本次草稿，密钥或地址变化时清除检测结果。通用设置只保留本地数据与备份设置。
- 服务商预设包含 OpenAI / 兼容服务、Gemini、DeepSeek、Claude、千问与豆包 / 火山方舟，预填官方兼容地址并提供密钥管理入口；豆包继续保存为 `ark`，兼容已有模型配置。服务商参数差异与工具调用元数据保留统一维护在 `packages/ai`，不在页面拼装专属请求逻辑。
- 常用模型统一维护在 `editor/toolbar/modules/ai/modelPresets.ts`，仅在添加弹窗中按服务商提供快捷填写，也允许手动输入。点击预设填入模型 ID，别名为空时补充名称；不提供未收录或下线判断，添加仍需连接检测。添加后的配置及后续型号变更由用户自行维护，预设更新不修改已有模型和角色绑定。
- 正文生成与改写统一使用 `packages/resume-agent/writingRules.ts`：`CONTENT_ACTION_RULES`（正文操作规则）、`getWritingRule`（按操作与类型取规则）和 `ASSISTANT_WRITING_RULES_TEXT`（助手写作约束）由同一事实源维护。
- 导入解析忠实转换原文；面试内容由独立面试智能体按真实作答生成，不加载简历正文起草规则。
- Web 侧负责入口、引导和简历数据适配；请求、任务、技能与工具实现在智能体包中维护。页面不得直接调用模型实例。
- AI 生成简历的输入、生成、预览与取消维护在 `components/aiGenerate/`，`components/aiResumeGenerator.vue` 提供弹窗形态、`generate/` 提供页面形态，两者共用同一流程；入口只负责带入来源样式与创建简历，不另写生成逻辑。
- `assistant/useResumeAssistant.ts` 组装本轮能力，`assistant/flows.ts` 维护功能引导；任务规则和技能不能在页面重复定义。

### 读取、写入与撤回

- 每次基于简历作答或修改都重新读取真实数据。默认读取所选模块，无选择时读取整份简历；整份任务显式固定本轮范围。
- `resumeModuleKeys`（本轮模块范围）、`resumeScope`（本轮读取范围）与脱敏设置在请求期间固定；旧请求结束不得清除新请求上下文。
- AI 读取返回 `title`（模块展示标题）与 `data`（业务数据），不携带编辑器状态；写操作使用稳定模块标识，不用展示标题代替。
- 媒体处理以 `packages/resume-core/mediaFields.ts` 为准，只裁剪读取副本；请求前后不得删除、还原或覆盖原简历媒体。
- AI 与导出共用脱敏配置；隐私标记和受保护字段保持只读，不猜测真实内容，也不把脱敏标记写回原数据。
- `propose_resume_edits` 校验后执行完整语义操作；校验失败不写入，执行部分失败时重新读取，仅重试未成功操作。
- 写入、改动清单和撤回都以实际成功结果为依据。取消、切换简历或切换会话后，旧请求不得继续写入或覆盖新状态。
- 翻译仅在本轮完整写入成功后切换展示语言；撤回须恢复内容、媒体和展示语言。
- 正文字段快捷处理只写当前目标，保留请求期间的手动编辑；生成、续写和改写先展示候选，再由用户采用。

### 修改同步

- 能力入口或流程变化：核对引导、建议卡片、任务分派与对应技能，并同步学习中心。
- 字段、格式或布局形态变化：同步契约、读取、写入校验、快捷处理、完成度与范本。
- 读取、脱敏或媒体变化：核对首次及重复读取、请求生命周期、撤回和源数据保留。
- 写入、翻译或报告变化：核对工具描述、成功凭据、失败重试与解析约束。
- 六维评分固定为信息完整度、阅读效率、职业契合度、职业成就、发展潜力和职业稳定性；无判断基础时使用空值，总分由有效维度计算。

## 存储、导入与导出

- 缩放旁提供批注显隐按钮，状态仅保存在当前预览会话；隐藏时收起卡片、连线及查看弹层，保留添加入口、模块数量和入口列占位。点击数量重新展开查看，隐藏时新增只更新数量，不主动展开内容，不删除已保存批注。
- 批注归所属内容持有：普通模块保存在 `data.<模块>.ui.reviewComments`（模块批注列表），列表条目保存在 `data.<模块>.list[].ui.reviewComments`（条目批注列表）。每条批注只保存编号、正文和解决状态；模块标识及条目下标由展示层汇总时派生，不持久化。定位直接读取模块或记录标记，不使用引用文字和字符偏移；修改正文不影响关联，记录排序时批注跟随，删除记录时批注一起删除。
- 批注字段与操作以 `domain/resume/comments.ts`（批注领域入口）为准，预览通过简历 Store 的汇总集合和新增、更新、删除接口访问。页面只维护 DOM 锚定、卡片位置与连线，不直接操作持有者的存储路径；不保留旧结构兼容、字段回退或迁移逻辑。
- 批注卡片默认收起并显示两行摘要，桌面和移动端共用唯一展开编号。点击标题展开或收起，展开其它卡片时自动收起前一条；新增及桌面点击模块数量时展开目标卡片，卡片尺寸变化沿用现有避让布局。定位、解决状态和删除按钮固定在标题栏，收起时仍可操作；正文展开区只保留编辑，不由标题点击触发定位。
- 模块悬停时在纸张右侧外部显示批注图标，新增批注按悬停或当前编辑的记录归属保存，模块标题入口归模块自身持有，不读取文字选区；模块外侧数量汇总模块和各条目的批注，点击定位对应卡片。批注不修改标题文字或样式，不在正文绘制高亮；弹窗只填写新批注，提交后才写入，取消不创建空批注。卡片在纸张右侧直接编辑，与纸张共用滚动坐标，通过反向补偿保持卡片、按钮、间距及连线的屏幕尺寸；自适应缩放先扣除固定批注列宽度，再计算纸张比例。按所属模块或记录位置排序避让，入口独占外部一列，连线仅绘制在纸张右边缘与卡片之间，不设置文字失效提示。卡片、数量、入口和连线使用编辑操作排除标记，不进入只读预览、AI 业务快照及投递正文导出。完整 JSON 备份保留批注。
- 窄屏及不支持悬停的触屏设备隐藏页边列和连线，不额外压缩纸张；批注组件挂载在缩放画布外，仅桌面页边内容传送回画布。在未缩放的预览视口右下角显示批注入口，按模块在全屏弹层查看和新增。新增弹层的操作区固定、正文使用 `SfScrollbar`，触屏卡片使用正常字号与触摸区域，输入字号避免聚焦自动放大；卡片标题可关闭列表并返回原文。桌面和移动端共用 `preview/commentCard.vue`（批注编辑卡片）与 Store 操作，不维护两套批注字段。

- `usage.tags`（简历分类标签列表）保存文字标签，统一去除首尾空白、空项和重复项；旧简历缺失时按空列表处理。我的简历卡片展示前三个标签，右键与更多菜单共用修改弹窗，按简历编号显式保存；完整备份保留标签，投递正文不包含标签。普通复制继承原标签，岗位适配另存时追加“公司 · 岗位”标签，公司为空时只使用岗位名称。

- 浏览器保存、JSON 完整备份和本地目录备份用途不同；保存失败应明确提示，临时读取失败不能被当作简历不存在。
- 简历剩余名额统一由 Store 按完整未删除目录计算，不能使用已加载正文数量替代。AI 新建、文档解析导入和岗位版本生成在模型请求前检查，确认创建时再次检查；岗位适配在开始分析前即检查可创建数量，避免先消耗请求再发现无法另存；普通优化同样在进入流程和请求前检查容量。新建、优化、岗位适配统一复用 `components/aiTask/` 的容量提示，新建与优化复用执行状态及完整简历预览，表单内部滚动、底部操作固定。
- 持久化、导出备份与本地自动备份共用配置压缩入口，只保存主题编号及用户覆盖项；运行时按主题展开。
- JSON 导入校验根结构、模块顺序和记录对象；文档解析先过滤字段、清洗正文并展示预览，确认后才创建简历。
- 隐藏内容不进入对应投递导出；脱敏导出使用独立副本，不修改原数据。完整 JSON 备份保留原始数据，不是脱敏分享文件。
- 智能一页必须等待有效测量，确认真实页面计划；失败或超时恢复原参数，不以溢出的一页计划报告成功。
- 智能一页试算与回滚不进入撤销历史，成功后仅记录一次最终排版；正文至少保留14像素，单次最多缩小2像素，行高不低于默认值。可读范围内放不下一页时恢复原排版。

## 主题与分页

- 用户配置仅保存可调参数；版式、边框、纹理等固定外观由主题声明，不能在简历快照中另存一份。
- 页面边距与模块间距由公共布局结算，主题装饰遵循共享几何与测量协议；主题不另建分页逻辑。
- 设置限制由实际主题声明，展示原因并阻止受限选项与重置写入，不维护重复的主题名单。
- 新增或调整主题、测量、分页时分别遵循对应目录的长期约定，不把细节或验证日志追加到本文件。
