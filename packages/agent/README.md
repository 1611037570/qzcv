# 通用智能体组装

本包依赖 `@snowflake/ai`，负责智能体运行器、工具循环、`createAgent` 与只读参考资料工具。不依赖简历、面试、页面或状态管理。

- 模型、提示词、工具、完成校验和运行回调均由业务方注入，不内置业务角色或默认领域规则。
- 每次创建使用独立运行器，消息副本、工具加载状态与取消操作不跨智能体共享。
- 模型请求与流式解析由 `@snowflake/ai` 负责；本包负责工具调度、运行取消和通用完成回调。
- 工具循环与完成检查的默认上限统一为九十九轮；同一工具、错误类别、稳定编码与目标累计三次失败时立即退出，不再按说明文字比较。无关工具成功不清除其他工具的计数，同一工具成功后清除自身各类失败计数；完成检查按稳定原因与目标独立累计。未完成交给业务层保留有效结果，运行记录标为失败。
- `runtime/failure.ts` 统一参数错误、工具缺失、业务拒绝和执行异常；模型收到的错误信封包含 `failure`（结构化失败）与可选的 `details`（业务原始结果或修正指引）。业务结果在证据层保持原样，部分成功不被全失败覆盖。执行异常默认停止，工具缺失允许重选，宿主可明确提供恢复结果。
- `run`（执行入口）与 `onFinal`（结束通知）共用 `AgentRunResult`（结构化运行结果）：`status`（完成、未完成、等待、阻塞、取消或异常）、`answer`（已验收正文或未完成说明）、`steps`（实际开始的推理轮数）、`reason`（稳定停止原因）、`toolFailure`（导致停止的工具错误）及 `error`（原始异常）。取消和异常不采用未验收的流式候选作为答案。
- `beforeFinal`（完成检查）返回明确状态；重试必须提供 `issue`（稳定原因），业务暂停明确返回等待或阻塞。只接受完整文本的业务入口可使用 `getCompletedAgentAnswer`（提取完整回答），其余入口直接消费结构化状态，不从回答文字推断执行结果。
- 简历写入证据、任务规划和字段处理规则留在简历智能体；面试轮次与评价规则留在面试智能体。
- 原有工具循环测试随运行器迁入本包，可用 `pnpm --filter @snowflake/agent test` 执行。
