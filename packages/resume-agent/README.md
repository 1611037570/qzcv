# 简历智能体包说明

本目录集中维护简历范围内的全部 AI 能力。编辑器、导入页面和助手只负责收集输入、选择能力并展示结果。

本包通过 `packages/agent` 创建简历智能体，复用 `packages/ai` 的基础模型能力与 `packages/resume-core` 的公共数据能力；本包只维护简历场景的提示词、任务、工具和写入验收。面试由 `packages/interview-agent` 独立维护。

目录职责：

- `request/`：简历业务模型选择、一次性请求、响应解析与文案。
- `tasks/`：正文处理、简历导入、普通会话及按入口标识懒加载的专用任务注册表。
- `runtime/`：维护请求范围内的统一 Agent 会话和任务运行内核；通用操作规则、任务数据模型、完成策略、证据查询和工具执行账本分别保持独立，会话负责入口任务解析、工具装配、ReAct 执行和结构化证据通知。
- `runtime/resumeChatSession.ts`：独立的只读聊天入口，复用通用模型与读取循环，不建立任务契约或进行修改验收；仅接受宿主的简历读取接口，在本入口装配简历与参考知识读取工具。基础编写规范来自共用规则，具体写作方法与行业资料按需读取，文案只在回答中交付。
- `prompts/`：助手反思和其他跨入口共用提示词。
- `skills/`：简历专属技能与能力目录；行业资料从公共包读取，面试技能不在本包。任务规划只读取摘要，正文按需加载。
- `tools/`：简历读取、写入、语言切换、统一参考知识读取、写入校验及供运行时执行前置证据检查的工具效果元数据。
- `context/`：声明宿主需要提供的简历数据读取上下文。
- `reports/`：AI 评分报告解析与结构校验。
- `tasks/runOneKeyOptimization.ts`：一次性优化执行入口，复用统一 Agent 会话、语义化工具与宿主长上下文压缩，不暂停追问；真实修改与报告展示分开验收，报告格式问题不丢弃内容，中断或失败后可返回明确标注的有效部分草稿。
- `tasks/optimizationEligibility.ts`：页面与执行层共用的优化前内容检查；只有身份信息、空模块、日期或占位文本时，在创建 Agent 前直接拦截，不调用模型生成“无法优化”的报告。部分模块缺失不作为拦截条件。
- 一键优化提供通用能力目录，由 Agent 根据目标选择写作、匹配、评估与参考知识，保留真实读取和修改后复核的必要约束；`reports/optimizationReview.ts` 根据原始数据与最终草稿生成净改动和真实摘录，模型只补充原因和建议，缺少评分不显示零分，未完成时不展示评分。宿主回滚失败批次，在用户明确选择使用后才写回原简历；部分结果可从保留草稿继续处理。
- `tests/`：本包的 Vitest 测试用例。
- 所有入口沿用九十九轮执行上限及同一失败三次退出；评分缺口在本地一次核对并汇总，不逐项请求模型。未完成时透出实际停止原因，真实成功的草稿修改仍可预览与保留。
- 优化与岗位定制将六维评分纳入最终交付，和内容说明在同一次最终回复生成；缺失项批量反馈，只修正报告。评分检查和展示共用数值归一规则，信息完整度与阅读效率必须评价，确实不适用的其余维度允许为空，不伪造分数。
- `writingRules.ts`：所有简历正文生成与改写共用的写作规则。
- `host.ts`：宿主注册简历模型选择与文案的入口；公共字段与媒体声明从 `@snowflake/resume-core/host` 独立注册。
- `index.ts`：提供给其他模块的统一公开出口，只暴露读取与执行能力。

生成请求约定：

- 空内容处理与可选字段边界只维护在 `writingRules.ts` 的 `DRAFT_REQUEST_RULE` 和 `OPTIONAL_FIELD_RULE`，由任务运行时统一注入一次；常驻提示、任务技能、字段表和页面入口不再重复定义。
- 目标必填内容为空时直接起草，可选字段默认不补，仅当前记录已使用或用户明确指定时操作；字段存在、空值和默认值不算已使用，新增记录不自动沿用其他记录的可选字段。
- 正文的生成、续写、更专业、更凝练、更详细统一由 `writingRules.ts` 的 `CONTENT_ACTION_RULES` 定义，字段任务与助手技能共用；富文本入口只收集操作、资料并展示候选。续写任务仅返回新增正文，由调用方清洗原文后追加；助手写回完整字段时同样保留原文。有效正文通过共用的 `richTextToPlainText` 安全解析、解码实体后判断，空白输出不得借原文通过校验。
- 草稿保留已知事实，未知自由文本身份字段使用占位，未知日期与未确认枚举留空或不提交；运行时不继承上一轮等待状态作为必须继续追问的理由，当前简历的添加或修改仍须完成真实写入。
- 新建入口只声明模块和布局，字段表只说明属性与格式，任务技能保留各自的写作方法与特殊约束；通用行为调整只修改共用规则，不在各层追加补丁。按执行规范未运行构建、测试或模型请求验证。

依赖约定：

- 本目录依赖 `@snowflake/agent`、`@snowflake/ai` 与 `@snowflake/resume-core`，不依赖面试智能体，不得导入 Web 路径别名、组件、Store、表单配置或国际化实现。
- 页面和助手不得直接调用模型实例的 `request` 或 `react`，统一经过本目录。
- Agent 对话与执行功能入口统一创建 `ResumeAgentSession`，页面不得直接装配任务运行时、控制工具或 ReAct。
- Chat 会话通过 `createResumeChatSession` 创建，宿主只传入 `ResumeChatContext` 读取接口，不传工具集合或写入执行器。两种模式共用技能注册目录、正文加载器与分片去重；Chat 允许按需读取任务技能作为写作参考，不改写其角色，不改变 Agent 的任务注册与完成策略。新增只读工具统一在 Chat 入口装配，不再维护第二份工具名称白名单。
- Web 宿主分别注册公共简历字段、简历智能体与面试智能体；本包通过公共数据包消费字段与媒体契约，不重复声明业务字段。
- 简历数据读取范围、脱敏、媒体裁剪和 Pinia 写入由 Web 适配器负责，本包只接收 `ResumeDataContext` 与语义化写入接口。
- 宿主可通过 `getResumeModuleKeys`（读取完整模块标识的回调）提供字段归属依据；求职意向存在时，按需字段契约排除个人信息中的同名求职字段，写入校验同步拦截错误归属。模块标识不扩大内容读取或写入范围。
- 参考知识加载器统一向注册的加载函数传递 `SkillLoadContext`（知识加载上下文），不按技能编号分支或直接导入具体技能。字段契约通过公共层的 `resolveResumeSchemaForModules`（按当前模块解析字段契约）生成，写入工具直接读取公共归属规则并从契约取得模块名称。
- 会话返回通用层的 `AgentRunResult`（结构化运行结果），完成、等待、阻塞、未完成、取消和执行异常明确区分；任务快照与写入证据单独保留。优化入口直接使用停止原因并保留有效草稿，不解析最终文字判断状态；生成入口只接受通过完成校验的草稿。业务字段错误沿用校验编码和操作位置计数，前置证据不足与重复失败调用使用明确原因编码。
- 任务能力选择与完成判断由本包运行时负责；通用 Agent 根据用户目标与可用工具安排操作，任务层提供本轮目标、范围和验收要求；选中的技能负责内容判断和写作方法，一键按钮可指定优先技能并按任务选用其他能力，规划工具按需加载并返回正文，参考知识只通过统一读取工具按需加载；工具自行判断执行结果，功能入口和交互流程属于助手页面。

测试命令：

- `pnpm --filter @snowflake/resume-agent test`：先构建 `@snowflake/ai`，再运行本包的 Vitest 用例。
- `package.json` 中的 `test`：本包测试入口；`vitest`：测试运行器开发依赖。
